# LeafStarter 规划

把「方块补给」（Minecraft 版本与加载器下载器）做成一个真正能用、而且让人想换过来的 Minecraft Java 版启动器。

带 **【待定】** 的地方需要先拍板，见第 3 节。

---

## 0. 现状：方块补给 0.1.0 已经有什么

| 模块 | 现在做什么 | 在启动器里怎么用 |
|---|---|---|
| `net.rs` | 多源下载：URL 改写、测速打分、按文件回退、限流冷却、SHA1 校验 | **原样复用**，所有下载都走它，也是「快」这个卖点的底子 |
| `mojang.rs` | 版本清单；版本 JSON → 文件清单；加载器 JSON 合并成独立版本 | 复用来「补全文件」；新增 `inheritsFrom` 链解析 |
| `loaders.rs` / `forge.rs` | Fabric / Quilt / Forge / NeoForge 版本列表与安装（含处理器） | 保留，作为「新建实例」 |
| `java.rs` | 找本机 Java；下载 Mojang 运行时 | 扩展为按版本 JSON 自动选、按 component 下载 |
| `launchers.rs` | 识别本机启动器和它们的 `.minecraft` | 演变为「游戏目录」：别的启动器的目录直接导入、直接启动 |
| `platform.rs` + `McBridgePlugin.kt` | 安卓：查已装启动器、文件授权、读写 ZL2 / FCL / Pojav 的目录 | **跨端卖点的底子**：别人没有的能力 |
| `install.rs` / `task.rs` | 安装流程；任务进度推送 | 任务系统泛化 |
| `src/` | 原生 HTML/CSS/JS 前端 | 保留技术栈，**交互重做**（见第 2 节） |
| `site/` | 官网 + R2 发布 + 下载统计 | 加自动更新接口、CurseForge 代理 |

## 1. 竞争力：凭什么一看就想下载

崩溃分析、整合包、Mod 下载、正版登录这些，PCL / HMCL 都有，做了只算及格，不会让人换。要有一句话就能说清、别家给不了的东西。

### 主打：手机电脑，同一个世界

> 在家用电脑玩的存档，到学校打开手机接着玩；回家再接着用电脑玩。

- **为什么是我们**：要做到这一点，得同时有桌面启动器和一个能读写安卓启动器（ZL2 / FCL / Pojav）目录的手机端。后者是方块补给已经做好的、最难的一块，别人没有。
- **做法**：以 LeafHub 账号为中心。电脑端退出游戏后自动上传开了同步的世界；手机端打开 LeafStarter 时拉下来，写进你常用的那个安卓启动器的目录。手机玩完回到 LeafStarter，再传上去。
- **同步的单位是「实例」**：MC 版本、加载器、Mod 列表、配置、存档一起同步，两边版本始终一致，不会出现用低版本打开高版本存档把世界弄坏的事。Mod 两边装的是同一个文件，不会因为版本不同出问题。
- **防冲突**：一边在玩时，另一边打开会提示「电脑上正在玩」；每次上传保留历史版本，坏了能退回去——顺带也就有了「存档云备份」。
- **限制要说清**：手机端只能在打开 LeafStarter 时同步（安卓启动器退出游戏时不会通知我们）；Mod 在手机上能不能跑，取决于安卓启动器本身。
- 存储复用 LeafHub 已有的对象存储；收不收费见 D11。

### 第二卖点：双击图标，直接进游戏

日常用启动器，99% 的时候只做一件事：进游戏。那就让这件事不需要看界面。

- 设置里打开「直接启动」后，双击 LeafStarter 图标就直接启动上次玩的实例，屏幕角落有 3 秒「取消」；要进界面就按住 Shift 再双击。
- 每个实例可以生成桌面快捷方式；任务栏图标右键列出最近玩过的实例，点一下就启动。
- 打开界面时，最近的实例已经选中，按回车就启动。

### 第三卖点：低配电脑也流畅

用户里有很多拿轻薄本玩的学生。

- 新建实例时选「流畅优先」，会自动加上一组口碑好的优化 Mod（Sodium、Lithium、FerriteCore 之类，按加载器和版本挑，都来自 Modrinth），再按内存和显卡调好 JVM 参数和画面设置。
- 已有的实例也能一键加上，一键撤掉。

### 打底（必须做好，但不当卖点）

- **快**：多源下载已经有了；启动前的检查和补全并行做，目标是从点「启动」到游戏窗口出来，不比直接点官方启动器慢。
- **出错就修好**：不只是说「Java 版本不对」，而是给一个「换成 Java 17 重新启动」的按钮。
- 崩溃分析、整合包、Mod / 资源包 / 光影管理、正版 / 离线 / 外置登录。

### 下一阶段：和朋友联机

国内玩家呼声最高的功能，但要服务器带宽，成本和方案（自建中继，或集成开源的组网方案）单独评估，见 D12。

官网首屏一句话：**手机电脑，同一个世界。**

## 2. 交互：为什么不顺手，改成什么样

### 2.1 现在的问题（从代码里量出来的）

「挺弹」恰恰是问题所在：第一次看觉得灵动，每天用几十次就变成了等待。

| 现象 | 代码里的事实 | 用起来的感觉 |
|---|---|---|
| 切页要等 | 每次切页，内容从下往上弹入：460ms 带回弹，加最多 150ms 错峰，**约 0.6 秒才停稳** | 手比眼快，点下去时目标还在往上走 |
| 列表飞入 | 切筛选时最多 24 行依次飞入，最后一行约 **0.7 秒**才到位 | 想点的那行还没落定 |
| 余光里总有东西在动 | 背景两团光斑无限旋转（60 秒、75 秒一圈），叠在毛玻璃面板后面；状态点、进度条也一直在闪 | 不看它也会被它吸引注意力；文字对比度跟着背景变 |
| 位置不固定 | 每页顶部一个大标题，切页时文字换掉；切页还会自动滚回顶部，回来时列表位置丢了 | 同一个按钮每次出现在不同的高度 |
| 关键动作藏在弹窗里 | 装一个版本要进弹窗走好几步；弹窗出现也带缩放回弹 | 每次都得「看」着操作 |
| 没有键盘 | 整个前端没有任何键盘处理，`Esc` 关不掉弹窗，回车不能确认 | 手离不开鼠标 |
| 打开就是目录 | 首页是「全部版本」列表，不是「我的游戏」 | 每次都要先找 |

### 2.2 新的原则：不用看也顺手

1. **位置恒定**：启动按钮、实例列表、导航，在任何页面都在同一个位置，加载前后不挪动（数据没来时用同尺寸的占位）。
2. **动画只说明变化，不表演**：高频操作（切页、切标签、打开列表）不做动画，或者只用 120ms 以内、不回弹的淡入；回弹只留给低频的时刻（安装完成、第一次进游戏）。背景静止。
3. **实底，不用毛玻璃**：面板不透明，文字对比度固定；背景图可以有，但不在文字后面。
4. **不打断**：主要流程不用弹窗，改成侧边面板或页内展开；删除这类操作不弹确认，直接做（进回收站）并给「撤销」。
5. **键盘可达**：回车启动、↑↓ 选实例、`Ctrl+K` 命令面板（「装 1.20.1 Fabric」「打开 mods 文件夹」「启动 xxx」）、`/` 搜索、`Esc` 关闭、`Ctrl+1…5` 切页。
6. **记住上下文**：上次的页面、筛选、滚动位置、选中的实例。
7. **默认就对**：Java、内存、版本隔离这些自动选对，大多数人一辈子不用打开设置。

### 2.3 新布局

- **左栏是「我的实例」**，常驻：图标、名字、版本、上次游玩；顶上是搜索和「新建」。
- **右边是选中的实例**：大启动按钮固定在右下角；下面是 Mod / 存档 / 截图等标签页。
- **账户**在左栏底部，一下就能切。
- **下载、任务、设置**从顶部的窄导航进，或者直接用 `Ctrl+K`。
- 视觉延续 LeafHub 的配色和衬线品牌字，但扁平、紧凑：列表行高 36–44px，圆角收小，正文用无衬线字体。

### 2.4 怎么验证

你说不清哪里不对，那就让手来判断：先做一个可以点的原型（新布局 + 首页 + 实例页，用 mock 数据），和现在的版本并排各用一天，确认手感对了再全面铺开（M1）。

可以量的验收标准：
- 老用户从双击图标到游戏开始加载：0 次点击（直接启动）或 1 次（回车）。
- 任何切页后 100ms 内目标可点，之后不再移动。
- 高频路径全部能用键盘完成。

## 4. 总体架构

### 4.1 核心概念

- **游戏目录**：一个 `.minecraft`。来源：自带默认目录、识别到的其他启动器目录、手动添加。
- **实例**：游戏目录里的一个版本（`versions/<名字>/`）。开启版本隔离时，游戏运行目录是 `versions/<名字>/`。
- **账户**：微软 / 离线 / 外置（authlib-injector）。另有 LeafHub 账号，只管同步。
- **同步实例**：开了同步的实例，在云端有一份清单（版本、加载器、Mod 列表、配置、存档快照）。
- **任务**：安装、补全、下载 Mod、导入整合包、下载 Java、同步、运行中的游戏。
- **设置**：全局 + 实例覆盖。

### 4.2 后端（Rust）

```
src-tauri/src/
  lib.rs              只留 setup 和命令注册
  commands/           按页面拆分的命令
  core/               net.rs  task.rs  util.rs  platform.rs
  game/               mojang.rs  loaders.rs  forge.rs  install.rs  java.rs  gamedirs.rs  optifine.rs
  launch/             resolve.rs（inheritsFrom）  files.rs（检查与补全）  natives.rs  assets.rs
                      args.rs（参数与 rules）  process.rs（进程与日志）  crash.rs（崩溃分析与修复）
  auth/               msa.rs  yggdrasil.rs  offline.rs  vault.rs（令牌加密存储）
  instance.rs         实例设置、复制 / 重命名 / 删除、桌面快捷方式、任务栏跳转列表
  sync/               （新）manifest.rs（实例清单与差异）  upload.rs / download.rs  lock.rs（谁在玩）
  content/            modrinth.rs  curseforge.rs（只连自家代理）  mods.rs  packs.rs  perf.rs（低配优化包）
                      modpack/{mrpack,curseforge,mmc,mcbbs}.rs
  world/              worlds.rs（level.dat）  servers.rs（servers.dat + 服务器探测）
  update.rs           自动更新
```

### 4.3 前端

```
src/
  index.html  styles.css  icons.js
  app.js              入口：路由、全局状态、快捷键
  core/               api.js（invoke / mock 切换）  store.js  ui.js（面板、撤销提示、命令面板）
  views/              home.js（实例列表 + 选中实例）  instance/*.js（概览 / 设置 / Mod / 存档 / 截图 / 服务器 / 日志）
                      download.js  accounts.js  tasks.js  settings.js  sync.js
  mock/               浏览器里直接打开时的演示数据
```

### 4.4 数据存放

- 应用数据目录：`settings.json`（带 `schemaVersion`）、`accounts.json`（令牌加密：Windows 用 DPAPI，安卓用 Keystore）、`gamedirs.json`、`cache/`、`java/`、`logs/`。
- 实例设置：`versions/<名字>/LeafStarter/instance.json`，跟着版本文件夹走。
- 云端（LeafHub 对象存储）：每个同步实例一份清单 + 按内容哈希存的文件（同一个 Mod 文件只存一份）+ 存档的历史快照。

### 4.5 安全

- 现在 `csp: null` 且 `withGlobalTauri: true`：一旦显示远程内容，被注入的脚本能直接调后端命令。要开严格 CSP；远程介绍在 Rust 里转 HTML 并清洗（`pulldown-cmark` + `ammonia`）。
- 访问令牌不落日志，导出日志和崩溃报告时打码。
- 整合包、Mod、同步下来的文件一律做路径穿越检查。
- 启动前命令、wrapper 命令只能用户本人在设置里填，整合包和同步都不能带进来。

## 5. 功能

### 5.1 启动核心

点「启动」之后：

1. **解析版本**：沿 `inheritsFrom` 合并；`jar` 字段决定客户端 jar。
2. **选 Java**：实例指定 > 全局指定 > 自动。自动按 `javaVersion.majorVersion` 选「刚好满足」的那个，不选最高的；没有 `javaVersion` 的老版本按 Java 8。找不到就按 `javaVersion.component` 下载 Mojang 运行时。
3. **准备账户**：微软令牌快过期才刷新；外置登录先校验再刷新；离线生成 UUID。
4. **补全文件**：默认按大小快速检查，可选完整 SHA1；缺的多源下载。和第 2、3 步并行。
5. **natives**：1.18 及更早的 `natives` + `classifiers` + `extract.exclude`，和 1.19 起库名带 `natives-windows` 之类分类器的写法，统一解压到 `versions/<名字>/natives-<系统>-<架构>/`，跳过 `META-INF`。
6. **旧版资源**：`virtual` 索引拷到 `assets/virtual/legacy`，`map_to_resources` 拷到 `resources/`。
7. **拼参数**：新写法 `arguments.jvm / game` 按 rules（系统、架构、features）判定；老写法 `minecraftArguments` 自己补 JVM 参数；替换全部占位符；加内存、用户参数、log4j 配置、外置登录的 `-javaagent`、窗口大小、自动进服（1.20+ 用 Quick Play，老版本 `--server` / `--port`）。Java 9+ 用 `@参数文件` 规避 Windows 命令行长度上限。
8. **起进程**：Windows 用 `javaw.exe`、不弹控制台；支持 wrapper 和启动前命令。
9. **日志**：实时推到日志面板；解析官方 log4j 配置输出的 XML 事件；每次运行存一份。
10. **状态**：游戏窗口出来后按设置隐藏 / 最小化 / 关闭启动器；退出码非 0 且不是用户结束的 → 崩溃分析；开了同步的实例 → 上传。
11. **多开**：同一实例重复启动先提示；不同实例可以同时跑。

### 5.2 直接启动

- 「直接启动」开关：双击图标 → 角落一个小窗显示「3 秒后启动 xxx · 取消」→ 启动 → 小窗消失，主界面从头到尾不出现。按住 Shift 双击则正常打开界面。
- 桌面快捷方式：带实例图标，命令行参数 `--launch <实例>`。
- 任务栏跳转列表：最近 5 个实例。
- 单实例：再次打开时把参数交给已运行的那个（`tauri-plugin-single-instance`）。

### 5.3 出错就修好

- 读本次输出尾部、新生成的 `crash-reports/`、`hs_err_pid*.log`、`logs/latest.log`、Forge 的 `logs/debug.log`。
- 首批规则，每条都带一个修复按钮：

| 原因 | 修复按钮 |
|---|---|
| Java 版本不对 | 换成合适的 Java 并重启（没有就下载） |
| 内存不够 | 调大内存并重启 |
| Fabric / Forge 缺依赖 | 从 Modrinth / CurseForge 补装 |
| Mod 重复 | 禁用旧的那个 |
| Mixin 失败（能定位到 Mod） | 禁用那个 Mod 并重启 |
| 文件损坏 | 补全文件并重启 |
| 显卡驱动 / OpenGL | 打开显卡驱动下载页 |
| 老版本游戏路径有 `!` 等字符 | 提示换目录 |

- 能提前查的放到启动前检查里。

### 5.4 账户

- **微软**：设备代码登录（桌面、安卓通用；桌面也可以浏览器 + 本地回调）。链路：Microsoft OAuth → Xbox Live → XSTS → Minecraft `login_with_xbox` → 查是否拥有游戏 → 取档案。XSTS 常见错误码给中文说明。刷新令牌加密保存，启动前按需换新。
- **离线**：用户名校验；UUID 默认与 Java 端一致的 `OfflinePlayer:<名字>` 名称 UUID。
- **外置**：authlib-injector，支持 ALI 自动发现；启动时加 `-javaagent` 和预取的服务器元数据。
- **LeafHub**：只用于同步，和游戏账户无关。

### 5.5 实例管理

- 左栏列表：按游戏目录分组；收藏、搜索、排序；同步状态小图标。
- 实例页：概览（启动、打开文件夹、补全、复制、重命名、删除进回收站、导出整合包、开关同步）、设置（每项显示「继承全局」或「已覆盖」）、Mod / 资源包 / 光影 / 存档 / 服务器 / 截图 / 日志。
- 版本隔离默认：装了加载器的实例隔离，原版共享。

### 5.6 资源中心

- **Modrinth**：公开 API，无需 Key。
- **CurseForge**（按第三方 API 条款）：
  - Key 只放在我们的服务器，客户端请求我们的接口，由服务器转发给 CurseForge；**服务器不缓存、不存储任何 API 返回的数据**（条款明令禁止）。
  - 文件由用户的客户端直接从 CurseForge 的 CDN 下载，我们不转存、不镜像、不改动文件。
  - 作者关闭了第三方分发的文件，API 不给下载地址 → 显示 CurseForge 项目页链接让用户手动下，下好后放进指定文件夹自动识别。
  - **不用第三方镜像加速 CurseForge 内容**；国内速度靠多线程和断点续传。
  - 每个项目显示作者、链接到 CurseForge 项目页。
- **MCIM 镜像**：只考虑用于 Modrinth 内容，先核实 Modrinth 的条款。
- 搜索、按实例自动过滤、两边都有的合并显示；安装时自动带必需依赖。
- 本地 Mod：解析 `fabric.mod.json` / `quilt.mod.json` / `mods.toml` / `neoforge.mods.toml` / `mcmod.info`；`.disabled` 启用 / 禁用；查重复、查缺依赖；按哈希反查更新。
- 低配优化包（5.8）。
- 资源包 / 光影 / 存档 / 服务器 / 截图：同上一版规划（读 `level.dat`、`servers.dat`、服务器探测、一键进服、截图墙）。

### 5.7 手机电脑同一个世界

- **电脑端**：实例页打开「同步」→ 登录 LeafHub → 首次上传整份实例（Mod 和库文件按哈希去重，公共文件只记来源不上传）。之后每次游戏退出自动上传变化的部分。
- **手机端**：列出云端的同步实例 → 选目标安卓启动器 → 下载 MC 版本 + 加载器 + Mod + 存档写进它的目录（复用现在的授权目录写入）→ 一键打开那个启动器。回到 LeafStarter 时检测存档变化并上传。
- **锁**：开始玩时登记「某设备在玩」，结束时释放；另一边看到会提示，可以强制接管（会先把对方最后一次上传的版本存成历史）。
- **历史**：每个世界保留最近若干个快照，可以退回。
- **流量**：只传变化的区块文件（世界存档按 `region/*.mca` 文件粒度比较）。

### 5.8 低配流畅

- 按「加载器 + MC 版本」维护一份优化 Mod 清单（以 Modrinth 上的版本兼容信息为准，不写死）。
- 新建实例时勾「流畅优先」；已有实例一键加 / 撤（撤掉时只删我们加的那几个）。
- 同时调：内存按物理内存自动分配、推荐的 GC 参数、`options.txt` 里的渲染距离等（只在首次创建时写）。

### 5.9 整合包

- 导入：Modrinth `.mrpack`、CurseForge zip（需手动下载的文件列出来）、MultiMC / Prism、HMCL / MCBBS。

### 5.10 Java、下载、设置、更新

## 8. 风险

- **CurseForge 审核和条款**：条款要求申请人年满 18 岁（或有完全民事行为能力）、所填信息真实；Key 不能给第三方；API 数据不能缓存。没批下来之前，资源中心先只接 Modrinth。
- **CurseForge 分发限制**：部分文件不允许第三方下载 → 引导手动下载。
- **跨端同步的边界**：手机端只能在打开 LeafStarter 时同步；部分 Mod 在安卓启动器上跑不了 → 同步前提示「这个实例里有 N 个 Mod 在手机上可能不兼容」（按已知列表）。
- **存储成本**：存档历史快照会涨 → 设保留数量上限、按内容哈希去重。
- **Forge 各代差异**：靠 M2 的验收矩阵回归。
- **杀毒软件误报**：没签名的程序又会起 Java 进程 → 尽早做代码签名。
- **商标**：不用 Mojang / Minecraft 的标志，注明「非 Minecraft 官方产品，与 Mojang 和 Microsoft 无关」。
- **新版本号格式（26.x）**：版本排序、Java 需求一律以版本 JSON 为准。
